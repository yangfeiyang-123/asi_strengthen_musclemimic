## 1. 一句话结论

目前不应该继续盲目增加 PPO 步数。

现有证据表明，模型已经能保持身体动作并偶尔碰到球，但碰球时拍头处于明显向下运动阶段，真实碰撞法向也把球反射向下。只训练 9 个腕部/前臂肌肉通道，即使给予更大的独立控制量，也没有找到任何一次向上的出球。下一步最有效的方法不是直接训练 v29/v30 到几百万步，而是先用单条可击中 feed 做“物理可达性优化”，证明在给定握拍、球拍固定方式、肌肉模型和动作轨迹下，最小右臂控制集确实能产生正的出球竖直速度和过网事件；找到成功控制序列后，再用它引导 PPO。

这是我对先前“重点训练腕部即可”判断的修正：腕部仍然是调整拍面的核心，但当前失败不仅是拍面角度问题，还包含拍头平移速度和击球时序问题，肩肘必须至少提供受限的协同修正。

## 3. 已经确认的实验事实

### 3.1 v24c 是接触基线，不是合格的回球策略

v24c checkpoint 491,520 在确定性 held-out 16 条 feed 上：

- 击球：2/16；
- 过网：0/16；
- 不摔倒：16/16。

因此它适合作为“保持动作与接触能力”的初始化，但不能被视为已经学会击球回球。

### 3.2 v26/v27 的方向奖励配置存在设计错误

v26/v27 使用过：

`racket_velocity_direction_fraction: 0.0`

这等价于只奖励拍面法向，不奖励真实拍面速度。对于当前动作，球拍在击球时的竖直速度大约为负 7 至负 12 m/s；仅把拍面法向调得看起来更合理，仍可能把球打向下方。这解释了此前“分项 reward 变大，但肉眼动作和回球没有变好”的一部分现象。

v28 起已把速度项占比改为 0.75，并使用真实碰撞事件处的 inverse-impact 目标。

### 3.3 v28 修正了奖励目标，但腕部训练没有解决真实回球

v28 训练到 163,840 步后，确定性 held-out 16 条 feed：

- 击球：1/16；
- 过网：0/16；
- 不摔倒：16/16。

真实碰撞事件处：

- 目标拍面速度误差仍约 8.5 m/s；
- 出球竖直速度约为负 7.8 m/s；
- 没有产生有效过网。

说明“正确奖励已经存在”不等于“当前动作自由度和探索方式能够到达正确解”。

### 3.4 v29 改善了接触，但没有改善回球方向

v29 增加了 `closest_approach_event_direction`：

- 真正击中时，只使用真实 event rebound 快照评价拍面法向和拍面速度；
- 没击中时，只在终止时对最接近球的一帧支付一次、带距离门控的 inverse-impact 分数；
- 保证最佳 miss 的理论收益仍低于最差真实 hit，避免策略靠“靠近但不击球”刷奖励；
- 全身 actor 和已经学到的右臂 adapter 冻结，只训练 9 个腕部/前臂输出。

v29 训练到 327,680 步后的确定性 held-out 16 条 feed：

- 击球：3/16；
- 过网：0/16；
- 不摔倒：15/16；
- 击中的是 episode 1、9、12，其中 episode 12 摔倒。

相比 v24c，接触数量从 2 增加到 3，但真实出球仍全部向下。因此继续把 v29 训练到数百万步，缺少物理可达性证据，不是高性价比选择。

## 4. 本轮最重要的物理诊断

### 4.1 直接把腕部 residual scale 从 0.25 放大到 1.0 是错误做法

如果把环境中的 9 个腕部通道整体从 0.25 放大到 1.0，继承策略原有的腕部动作也会一起放大四倍，而不是只放大新增修正量。38 条确定性 rollout 全部失去接触，0/38 击中。

所以，不能用“提高 residual scale”代替真正独立的增量控制头。

### 4.2 保留旧基线后，腕部独立控制仍没有产生向上出球

随后做了正确的补偿实验：

- 环境给腕部 1.0 authority；
- 继承动作先乘 0.25，使零扰动时与 v24c 的物理控制完全相同；
- 再独立加入腕部屈伸、桡偏/尺偏、旋前/旋后模式。

38 条 rollout 的结果：

- 15 条仍能击中；
- 正出球竖直速度：0 条；
- 最好的出球竖直速度：`-6.492 m/s`。

这比“腕部放大后完全碰不到球”更有判别力：它说明不是只有初始化被破坏，而是这些腕部模式本身仍不足以把当前向下的拍头运动改造成向上回球。

### 4.3 真实事件快照证明拍头和有效拍面都在把球导向下方

两条能稳定接触的 feed（9 和 12）的精确 event 快照如下。

Feed 12：

- 碰撞前球速：`[-0.913, -0.007, -6.077] m/s`
- 碰撞时拍面速度：`[7.598, 3.324, -6.857] m/s`
- 真正有符号的接触法向：`[0.531, 0.729, -0.431]`
- event rebound 后球速：`[5.592, 7.669, -10.434] m/s`

Feed 9：

- 碰撞前球速：`[1.594, 3.989, -7.456] m/s`
- 碰撞时拍面速度：`[-1.442, 6.416, -11.649] m/s`
- 真正有符号的接触法向：`[-0.199, 0.578, -0.792]`
- event rebound 后球速：`[-0.293, 8.507, -13.775] m/s`

这里要区分两个法向：诊断早期看到的“原始 stringbed 局部 +Z 轴”有时 z 为正，但物理接触会根据球位于拍面的哪一侧给法向乘以正负号。真实 event normal 的 z 为负，和实际向下反弹一致。inverse-impact 公式和碰撞法向没有发现符号 bug。

### 4.4 简单调整全局挥拍相位也不能解决

对 `swing_phase_advance_s` 做了 0.0、0.10、0.20、0.30、0.40、0.50、0.58、0.65、0.75 的 sweep，共 18 条 rollout：

- 0.58：2 次击中，0 次向上出球；
- 0.75：1 次击中，0 次向上出球；
- 其余相位：全部错失来球。

因此当前问题不能通过一个全局 phase offset 修好。右臂需要在保持接触位置的同时，局部改变击球前后的速度和拍面方向。

## 5. 当前根因判断

### 已确认

1. 发球轨迹本身通过了现有质量门禁，训练/验证数据无重复、无交叉污染。
2. 球拍质量、惯量、刚性连接和接触所有权通过合同检查，刚性漂移接近数值零。
3. inverse-impact 的法向符号和 event rebound 数学关系一致，没有发现“奖励方向写反”。
4. 当前真实击球发生在拍头明显向下运动时。
5. 9 通道腕部独立干预在已测范围内不能产生正的出球竖直速度。
6. v29 只提高了接触率，没有产生过网回球。

### 高概率判断，但尚未最终证明

1. 当前失败是“拍面旋转 + 拍头平移速度 + 局部时序”的联合问题，而不只是腕部角度问题。
2. 肩肘需要受限参与，给球拍中心提供向前/向上的速度；腕部负责最后的拍面修正。
3. PPO 从零探索成功事件的概率过低。没有任何向上回球样本时，仅依靠稀疏真实 hit 奖励，容易停在“接触更多但仍向下”的局部最优。
4. 现有右臂 residual authority 0.25 可能足够，也可能仍不足。必须先做可达性优化，不能靠长训猜测。

## 6. 我目前认为最有效的下一步

### 第一步：先做单 feed、短时域的物理可达性证明

不要立即训练 20M PPO。先选择当前能稳定击中的 feed 12，再用 feed 9 复核。

固定内容：

- Stage2 base policy；
- v24c actor；
- 全身非右臂动作；
- 发球轨迹；
- 球拍握姿和刚性连接。

只优化击球前后约 0.5–0.7 秒的 32 个右臂肌肉修正量。建议使用 MJX 批量 CEM、短时域 trajectory optimization，或可微优化；修正量用少量时间样条节点参数化，而不是每个仿真步一个自由变量。

目标必须按层级处理：

1. 首先保持真实 stringbed event contact；
2. 在击中前提下最大化真实 event 后的 `outgoing_velocity_z`；
3. 然后要求回球朝对方半场，即正确的 x 分量；
4. 再要求过网高度、落点和恢复；
5. 最后惩罚动作不平滑、能耗、饱和和摔倒。

这一阶段的通过标准不是 reward 变大，而是至少找到：

- 一条真实击中；
- `outgoing_velocity_z > 0`；
- 最好至少一条真实过网。

如果 32 个右臂通道、authority 0.25 能找到该序列，说明任务物理上可达，可以进入学习阶段。

如果大量优化仍找不到正 z，则依次审查：

1. 在不改变旧动作的前提下提高“新增修正量”的 authority；
2. 当前握拍刚性变换是否让肌骨腕关节的可用活动范围无法到达目标拍面；
3. feed 的接触点是否超出该动作的可击球工作空间；
4. 是否需要允许非常小的躯干/肩胛补偿。

在可达性证明失败前，不应再启动长时 PPO。

### 第二步：实现真正独立的分组增量控制

现有环境的组合形式近似为：

`full_action = clip(stage2_action + 0.25 * policy_action, -1, 1)`

当前 refinement adapter 是在 policy logit 上相加，虽然零初始化能保持起点不变，但它和继承动作共享同一个 0.25 物理缩放。若直接把环境 scale 改为 1.0，继承动作也被放大，接触立即被破坏。

更合理的组合应明确分开旧动作和新增修正：

`full_action = clip(stage2_action + 0.25 * inherited_action + alpha_group * tanh(delta_action), -1, 1)`

其中：

- `inherited_action` 永久冻结，确保初始动作逐位等于 v24c；
- `delta_action` 零初始化；
- 腕部、肘/前臂、肩部分别设置独立的 `alpha_group`、探索标准差和正则；
- 腕部承担拍面调整，肩肘只用满足拍头速度所需的最小控制量；
- 全身其他 322 个肌肉输出保持冻结。

这比给整个旧右臂统一放大 residual scale 更安全，也更符合“整体动作已经正确，只修击球瞬间”的目标。

### 第三步：用可达性优化得到的成功序列引导策略

一旦找到成功序列：

- 将成功的右臂修正轨迹作为 adapter 的短时行为克隆目标；
- 或启用只对真实成功事件生效的 successful-action imitation；
- 然后用 PPO 学会根据球位置、身体状态和 time-to-intercept 自适应调整；
- 先固定单 feed，再扩展到 16 条 jitter feed，最后扩展至 128 条训练 feed；
- 每次扩展必须由 held-out 真实击球与过网指标触发，不能只看 episode return。

### 第四步：设置严格的短周期停止条件

建议每 163,840 或 327,680 步做一次确定性 held-out 16-feed 评估。

继续训练的最低证据：

- 出现真实 `outgoing_velocity_z > 0`；或
- 出现真实过网事件；或
- event velocity error 和有符号法向误差同时、稳定下降，且 hit/no-fall 没有退化。

停止并回到控制设计的条件：

- 连续两个 checkpoint 仍为 0 次正 z、0 次过网；
- 只有 contact rate 增长，但 event 后的 z 速度仍为负；
- hit 增长来自摔倒、非 stringbed 接触或动作饱和；
- 训练 reward 上升但确定性 held-out 不提升。

## 8. 不建议继续做的事情

1. 不要继续追加 v29 步数并期待自然出现过网。
2. 不要仅依据 episode return 或分项 reward 上升判断成功。
3. 不要直接把继承策略的腕部/右臂 residual scale 从 0.25 改为 1.0。
4. 不要在没有正 z 或过网样本的情况下把 feed 一次扩到 128 条。
5. 不要把原始拍面局部轴当作真实碰撞法向；必须使用 event snapshot 中按球侧选择后的 signed normal。
6. 不要通过放开全身策略来掩盖右臂控制问题，否则会破坏 Stage2 已经学好的身体轨迹。

## 9. 需要进一步由你审查/决定的问题

1. 是否接受“先做单 feed 可达性优化，再恢复 PPO”的路线。
2. 是否坚持握拍刚性变换 `forehand_clear_rigid_v4_custom` 完全不变；合同通过只证明连接一致，不证明该握姿在肌骨腕关节活动范围内一定适合高远球。
3. 对最终动作的优先级：保持当前身体动作、真实过网、落点深度、自然腕部发力，四者的排序是否如本文假设。
4. 若 authority 0.25 的 32 通道右臂不可达，是否允许新增 correction 对腕部/肘/肩使用不同的小幅物理 authority，而不是统一放大旧策略。

## 10. 最终判断

目前得到的不是“模型再多训一点就会好”的证据，而是一个明确的可控性问题：当前策略能把拍子带到球附近，但碰撞发生时拍头速度和有效拍面方向共同指向下方；腕部单独修正尚未显示出足够的物理能力。

我目前最推荐的路线是：

**先证明右臂短时控制可产生一次真实向上/过网回球 → 再实现基线与 correction 分离的分组 adapter → 用成功轨迹初始化 → 最后用分阶段 PPO 泛化。**

这条路线比继续堆训练步数更慢于“立刻启动”，但能最快回答任务到底是否可学、缺的是奖励、控制权、握拍几何，还是探索样本，从而避免继续产生无法解释的长训练。
