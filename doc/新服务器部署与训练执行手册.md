# MuscleMimic 新服务器部署与训练执行手册

> 适用范围：在一台新的 Linux x86_64 NVIDIA GPU 服务器上，部署并验证
> MuscleMimic 的正手高远球 PEASD 实验环境；在所有门禁通过后，以一个全新的
> Stage-1 T0 seed-0 family 启动正式训练。
>
> 冻结日期：2026-08-12。本文固定到已经完成 clean-clone 验证的发布提交，不能把
> `main`、某个会继续移动的分支名或旧 checkpoint 当作等价替代。

## 0. 新服务器执行者先读这里

本项目的主实验是 **Partial-EMG Anchored Synergy Distillation（PEASD）**：

1. Stage 1 用视频重定向轨迹训练 full-354 肌肉 tracking teacher，并做
   T0–T4 matched comparison；少量 sEMG 只是 measured-subspace anchor，不是 354 维肌肉真值。
2. Stage 2 把 teacher 蒸馏成不依赖未来 reference、部署时不需要在线 EMG 的 direct/latent skill。
3. Stage 3 冻结 prior/decoder，用 LAB 和受限 residual 处理来球并检验真实击球。

正手高远球是 P0 主结果。本文只部署正式工作流和私有训练资产，不代表多 seed 实验已经完成，
也不允许把 dry-run、单测或旧 checkpoint 写成实验结果。

新服务器的首个正式任务是：在下述发布 snapshot 上建立**新的 matched family**，从
T0 seed 0、fresh optimizer 开始。禁止把它接到旧 `103f0b...` family 的 T0 seed 1/2，
禁止恢复旧 family checkpoint。后续 T0–T4 的 15 个叶节点必须保持同一个 source-tree
fingerprint、22/5 split、预算、验证调度和代码快照。

## 1. 硬性规则

- 正式训练只能从仓库根目录通过 `scripts/run_fullbody_training.sh` 启动。
- 禁止用 `python`、`.venv/bin/python` 或 `uv run fullbody/experiment.py` 直接启动 production run。
- 每个 run 只能选择一张明确的物理 GPU；进程内部的 CUDA device 0 是可见索引，不一定是物理 GPU 0。
- 必须设置 task-specific JAX cache key、append-only log，以及 Orbax save/restore 并发上限 4 GB。
- reward、termination、split、tube、mapping 或源码变化后，必须使用新 run id 和 fresh optimizer。
- 正式运行不允许 `--skip-gpu`、`--skip-tube`、`--allow-dirty-source`。
- 禁止出现 Hugging Face trajectory 下载。出现下载尝试说明本地数据绑定失败，必须停止。
- 资产清单含授权数据路径与哈希，不得提交到公开 GitHub。
- 不执行 `rsync --delete`，不整目录覆盖 Git 源码，不同步整个历史 checkpoint 根目录。

仓库根目录的 `AGENTS.md` 是最终训练启动合同；本文是它在新服务器上的逐步执行版。

## 2. 目标服务器准备与克隆

目标服务器需要：

- Linux x86_64、Python 3.11；
- 可用的 NVIDIA driver 和 `nvidia-smi`；
- `git`、`uv`、`tmux`、`rsync`、`wget`、`bsdtar`；
- 可写的大容量训练盘和 JAX compilation cache 目录；
- 到 GitHub、Python 包源和 W&B 的网络；
- W&B API key 或已登录账号。

先登录目标服务器，填写两个本机路径。路径不要使用本文中的占位符原样运行：

```bash

export PUBLISHED_SHA=250aa53777af7b19da748c60846a2665f0a1fdca
```

检查基础工具与 GPU：


## 3. 从源服务器迁移私有资产

这一节在**现有源服务器**执行。目标仓库必须已经按上一节创建。

先填写目标 SSH 信息；`TARGET_REPO` 必须与目标服务器上一节的绝对路径完全一致：

```bash
cd /data3/yangfeiyang/WorkSpace/musclemimic
export TARGET_USER=<target-user>
export TARGET_HOST=<target-host-or-ip>
export TARGET_REPO=/absolute/path/on/target/asi_strengthen_musclemimic
```

生成 action-owned 私有资产清单：

```bash
uv run --locked python scripts/build_training_asset_manifest.py \
  --action forehand_clear \
  --output /tmp/forehand_clear_assets.json \
  --files-from /tmp/forehand_clear_assets.files
```

生成器会验证 22 条训练轨迹、5 条 held-out validation 轨迹、release/QC、verified EMG tube
以及 SMPL-H，并排除 Git 已跟踪文件。核对清单身份：

```bash
grep -F '"file_count": 147' /tmp/forehand_clear_assets.json
grep -F '"total_bytes": 433080980' /tmp/forehand_clear_assets.json
grep -F '"manifest_fingerprint": "df89173e382cf5be18e8aabb4bb823dd882f57ed50f392b6a63cbc35e335ca13"' \
  /tmp/forehand_clear_assets.json
```

三条都必须匹配。然后按清单迁移，不使用 `--delete`：

```bash
rsync -a --info=progress2 --files-from=/tmp/forehand_clear_assets.files \
  ./ "${TARGET_USER}@${TARGET_HOST}:${TARGET_REPO}/"

rsync -a /tmp/forehand_clear_assets.json \
  "${TARGET_USER}@${TARGET_HOST}:${TARGET_REPO}/private_asset_manifest.json"
```

如需迁移某个已合法封存的 checkpoint，只能重新生成清单并显式添加
`--extra-path <exact-immutable-checkpoint-leaf>`；不要同步整个 checkpoint 历史目录。
本文的新 T0 seed-0 run 不需要旧 checkpoint。

## 4. 目标服务器执行 fail-closed preflight

回到目标服务器：

```bash
cd "$TARGET_REPO"
export PUBLISHED_SHA=250aa53777af7b19da748c60846a2665f0a1fdca
export EXPECTED_SOURCE_FP=0a61388a6ac0bde64f8e1d9c1f0572e90f4c13df26a50927bb454660a1b05954
export MUSCLEMIMIC_JAX_CACHE_ROOT=/path/to/large-writable-volume/jax-cache
export GPU=0
```

`GPU=0` 只是示例。先用下面两条命令确认目标物理卡存在且没有其他训练进程；若被占用，改成真正空闲的物理卡：

```bash
nvidia-smi -L
nvidia-smi -i "$GPU"
```

加载仓库路径绑定并执行完整预检：

```bash
source configs/env.sh

uv run --locked python scripts/server_training_preflight.py \
  --action forehand_clear \
  --physical-gpu "$GPU" \
  --jax-cache-root "$MUSCLEMIMIC_JAX_CACHE_ROOT" \
  --asset-manifest private_asset_manifest.json \
  --expected-git-sha "$PUBLISHED_SHA" \
  --expected-source-tree-fingerprint "$EXPECTED_SOURCE_FP" \
  --output server_preflight.json
```

硬门禁：

```bash
grep -F '"passed": true' server_preflight.json
test "$(git rev-parse HEAD)" = "$PUBLISHED_SHA"
```

如果报告不是 `passed: true`，立即停止。不要用 skip/allow 参数绕过错误。预检会验证：

- Git SHA、source-tree fingerprint 和 scoped source/config cleanliness；
- 目标 GPU、工具与可写 JAX cache；
- 22/5 action release、数值/视频 QC 和相对路径可移植 binding；
- verified PEASD tube；
- 147 个私有资产的大小和逐文件 SHA-256；
- SMPL-H neutral model。

再确认 JAX 经仓库 CUDA compatibility 入口看到了所选 GPU：

```bash
CUDA_VISIBLE_DEVICES="$GPU" \
scripts/run_with_cuda_compat.sh uv run --locked python -c \
  'import jax; print(jax.devices())'
```

输出应包含一个 GPU/CUDA device。这里显示的 device 0 是由 `CUDA_VISIBLE_DEVICES` 映射后的可见索引。

## 8. 启动后五项验收

不能仅凭 tmux pane 存活就报告启动成功。以下五项必须全部成立。

### 8.1 所有 22+5 条 trajectory 都从本地 cache 加载

```bash
grep -c 'Found existing retargeted motion file' "$TRAIN_LOG"
grep -nE 'Downloading GMR cache|Downloaded GMR cache|huggingface|hf_hub' "$TRAIN_LOG"
```

第一条计数至少应为 27。第二条不应有 trajectory 下载命中；若命中，按第 9 节立即停止。

### 8.2 checkpoint run manifest 已写入且合同正确

日志会打印：

```text
Checkpoint directory: <absolute-run-directory>
```

取出路径并检查 `<absolute-run-directory>/manifest.json`：

```bash
grep -n 'Checkpoint directory:' "$TRAIN_LOG" | tail -n 1
```

manifest 必须记录本次 `config_hash`、`run_id=forehand_clear_peasd_250aa_t0_s0`、
`total_timesteps=320000000`、fresh/no-resume、promotion、reward 和 terminal 合同。不要用旧 run 的
manifest 代替。

### 8.3 W&B 有真实 live run id 和 URL

```bash
grep -nE 'wandb:.*(View run|run URL|Run page|syncing)' "$TRAIN_LOG" | tail -n 20
```

还要打开 W&B 页面确认 run 正在更新；仅有本地 `wandb/` 文件夹不算通过。

### 8.4 Python PID 在预期物理 GPU

```bash
nvidia-smi -i "$GPU" --query-compute-apps=pid,process_name,used_memory \
  --format=csv,noheader
```

确认新 Python PID 出现在 `$GPU` 指定的物理卡，而不是仅根据进程内部的 device 0 判断。

### 8.5 已到 `Starting training...` 且没有 fatal traceback

```bash
grep -n 'Starting training...' "$TRAIN_LOG" | tail -n 1
grep -nEi 'Traceback|FATAL|CUDA out of memory|segmentation fault' "$TRAIN_LOG" | tail -n 20
```

第一条必须命中，第二条不应有新错误。五项全部通过后，才能报告：

```text
DEPLOYMENT_OK
git_sha=<40-char SHA>
source_tree_fingerprint=<64-char fingerprint>
run_id=<run id>
wandb_url=<live URL>
physical_gpu=<index>
python_pid=<PID>
checkpoint_run_manifest=<absolute path>
append_only_log=<absolute path>
```

## 9. 异常停止流程

以下任一情况必须停止：HF trajectory 下载、错误物理 GPU、manifest 合同不符、NaN/OOM、fatal
traceback、W&B 无 live run、数据数量不是 22/5。

只通过 tmux pane 发送**一次** Ctrl-C：

```bash
tmux -S "$TMUX_SOCKET" send-keys -t "$TMUX_SESSION:0.0" C-c
```

随后等待 Python PID 和 CUDA context 消失：

```bash
nvidia-smi -i "$GPU" --query-compute-apps=pid,process_name,used_memory \
  --format=csv,noheader
tmux -S "$TMUX_SOCKET" capture-pane -p -t "$TMUX_SESSION:0.0" -S -120
```

不要立即发第二次 Ctrl-C，不要 `kill -9`，不要删除 checkpoint。保留最近一个已经 finalized 的
Orbax checkpoint、完整 append-only log 和失败原因。确认 PID/CUDA context 消失后，再决定是否关闭
tmux session。修复 reward、termination、tube、mapping、split 或 source 以后必须换新 run id、
fresh optimizer；不得恢复不兼容 checkpoint。

## 10. 后续实验顺序

T0 seed 0 完成后，也不能直接跳到 T3。正式顺序为：

```text
T0 seeds 0/1/2
  → verified tube gate 复核
  → 三个 T0 fixed-endpoint post-hoc physiology
  → T1 seeds 0/1/2
  → T2 seeds 0/1/2
  → T3 seeds 0/1/2
  → T4 seeds 0/1/2
  → 15-leaf evidence index
  → T3 seed-0 opaque blind review
  → pairwise gate
  → T3 seed-0 teacher promotion
  → Stage 2 direct + latent family
  → Stage 3 H1/H2/H3 family
```

每个新 leaf 都要有独立 run id、tmux session、cache key、append-only log、W&B run 和 checkpoint
root。完整 PEASD 证据门、后续 pipeline 参数与人工 review 规则见：

- `docs/peasd_implementation_guide.md`
- `doc/实验计划/PEASD正式实验计划.md`
- `doc/实验计划/实验运行跟踪表.md`
- `docs/server_deployment.md`
- `AGENTS.md`
