# 肌肉生理约束实施契约 v2

本文记录《肌肉协同与肌肉内部约束.md》在仓库中的实际落点。它不是新的
生理学结论，而是训练、数据、artifact 和评估共同遵守的可执行契约。

## 已实施范围

本次完成 Phase 0、Phase 1 和 Phase 2 的安全基础与 diagnostics-only 接入：

1. policy action 继续使用 `[-1,1]`，`DefaultControl` 将它映射到 muscle
   actuator 的物理控制域 `[0,1]`；
2. raw `data.ctrl` 原样保留，effective excitation 唯一定义为对已核验
   `mjDYN_MUSCLE` channel 执行 `clip(raw_ctrl,0,1)`；
3. activation 只能通过 `model.actuator_actadr` 读取 `data.act`，不能用
   actuator id 代替 activation-state address；
4. physical dataset、NMF excitation basis、early-synergy action 和 frozen
   decoder 均升级到 v2，旧 artifact fail closed；
5. audit taxonomy 保留；curated taxonomy 新增 24 个诊断型
   `soft_compartment_group`，但 `hard_line_group` 仍为空，不向训练 reward
   加任何未经核验的等同约束；
6. decoder 同时输出裁剪前 excitation、裁剪后 excitation、越界比例和
   clip correction RMS，避免饱和把异常 residual 掩盖；
7. frozen decoder 的实际 W、coefficient transform、tonic、R、bounds 与
   `BodySynergyContractV2` 通过 execution binding 相互绑定；只让文件哈希
   自洽、但让声明契约与执行数组分离的 artifact 会被拒绝；
8. universal muscle checkpoint 同时绑定真实 policy action 顺序、
   `ctrllimited`、activation address、`DefaultControl/direct`，并要求 run
   manifest 与具体 Orbax leaf 内的 contract 一致；
9. `musclemimic_models` 与 lock file 精确固定为 `1.0.5`。
10. versioned continuity graph 精确枚举同侧躯干 28 条 chain、140 条 edge，
    全部 `review_status=provisional`、`training_enabled=false`；
11. PPO 可显式启用 activation-level continuity diagnostics，训练和验证同时
    记录 loss、violation、edge difference、activity gate 与 chain/edge coverage，
    但 `coefficient=0`，reward 和物理状态不变；
12. reward 代码路径已实现为 fail closed：只有 verified training chain、固定
    taxonomy/graph fingerprint 和离线标定的正系数同时存在时才能启用；当前仓库
    没有伪造这些证据，也没有修改默认生产配置。
13. Phase 3 的证据工具已实现：held-out raw rollout 的固定预算系数标定、只允许
    Batch-A EO/IO 的独立审核晋级、新 graph fingerprint、24 个 fresh-optimizer
    matched-seed 配置和 Pareto-aware 汇总报告。评估器还能从真实
    deterministic evaluate-all transition 中直接封装逐步样本，不接受手工汇总值；
14. Phase 4 的 Graph-NMF 已作为独立 opt-in 路径实现。正 `lambda` 只接受 verified
    graph，强制 `normalization=none`，标准 `lambda=0` 保持历史数值路径；graph
    lineage 会进入 candidate、basis、hybrid、action contract 和 frozen decoder；
15. asset smoke 覆盖 bare/racket 与 direct、fixed-W、W+R，并检查真实
    `data.act`、continuity、JAX eager/JIT、重复调用编译缓存和 host callback。

这些是代码与证据合同，不是实验结果。Phase 3 的实际 reward ablation 和 Phase 4
Graph-NMF 拟合/训练尚未执行；缺少真实 baseline rollout、独立审核、正式 W/R 或
promotion evidence 时不得生成替代数字。现已根据实际采集 profile 增加一份
`review_status=provisional` 的观测映射，但默认不得进入正式评估，更不得进入
reward 或训练。它没有把 DELT、PECM、LAT、gluteal heads 或左右同名
肌肉硬绑定。

## 三种信号不得混用

| 字段 | 定义 | 用途 |
|---|---|---|
| `teacher_ctrl_physical` | transition 后保留的 raw `data.ctrl` | 审计与迁移证据 |
| `muscle_excitation` | verified muscle channel 上的 `clip(raw_ctrl,0,1)` | command-level 诊断和 excitation NMF |
| `muscle_activation` | `data.act[actuator_actadr]` | activation-level 生理诊断；把它作为未来 IMR 首选对象是本项目的设计选择 |

`data.actuator_force` 还受到 force–length–velocity 和被动力影响，不能作为
IMR 的 activation 替代量。sEMG 是带有电极、volume conduction、
normalization 和串扰不确定性的观测，也不能直接改名为模拟 activation。

## 数据与 checkpoint 迁移

旧 physical dataset 只有在同时具备 raw ctrl、精确 actuator 顺序和明确
v1 metadata 时才允许迁移：

```bash
uv run --locked scripts/migrate_physical_excitation_v1_to_v2.py \
  --acknowledge-pinned-v1-model \
  /absolute/path/to/legacy_dataset \
  /absolute/path/to/new_v2_dataset
```

早期 v1 collector 没有写 `source_model_provenance`，因此这类历史数据必须
显式给出上述 attestation。它只声明数据来自本次审查重建的旧
MyoFullBody `[-1,1]` 运行时修改与固定的 `musclemimic-models==1.0.5`；
脚本仍会逐项核对 actuator 顺序、signed ctrlrange、模型维度、v1 affine
方程和全部 shard。若源 metadata 已带完整且精确匹配的模型 provenance，
则无需该参数。

迁移器不会修改源目录或覆盖目标目录。它保留旧
`muscle_excitation` 为
`legacy_muscle_excitation_ctrlrange_coordinate_v1`，再从 raw ctrl
重建 v2 excitation，并记录源/目标 shard hash、模型 hash、package
version、`requires_basis_refit=true` 和 `requires_fresh_optimizer=true`。

这不是 basis 或 checkpoint 的数值“修补”。迁移数据后必须重新拟合 NMF
basis、重新生成 decoder artifact，并从新 optimizer 开始训练。旧
full-354、synergy 和 residual checkpoint 不得续训。

恢复 checkpoint 时不能只信任所在目录的 `manifest.json`。validator 会同时
核对实际 restore leaf 的 finalized marker、`train_state`、
`config/metadata`、`metadata/metadata`、update number，以及 leaf/run/runtime
三方的 muscle/body contract。把旧 leaf 移动或软链接到一个 v2 run 目录不会
使它变成兼容 checkpoint。

ChinaJump root-control 配置因此使用新的 run id：
`chinajump_root_control_v2_stage1_body_excitation_v2`。正式启动仍必须遵守
仓库 `AGENTS.md`，通过 `scripts/run_fullbody_training.sh`；launcher 使用
`uv run --locked`，避免启动时依赖漂移。

## Taxonomy 与 IMR 启用门

运行时 anatomy manifest 将四类关系分开：

- `hard_line_group`：只有模型资产 provenance 能证明是同一解剖肌肉的
  numerical lines 时才可训练；
- `soft_compartment_group`：只做 dispersion 诊断；
- `observation_aggregate`：只描述 EMG/报告投影；
- `functional_synergy_region`：只用于 NMF 分区或 rank allocation。

导出 exact MyoFullBody taxonomy：

```bash
uv run --locked scripts/export_myofullbody_muscle_taxonomy.py \
  --disable-fingers \
  --expected-package-version 1.0.5 \
  --output /tmp/myofullbody_354_taxonomy.json
```

manifest 必须绑定 package version、XML hash、compiled model hash、ordered
actuator metadata、`dyntype`、`actnum`、`actadr`、ctrlrange 和 transmission
target。训练启用还必须满足：

1. group 类型为 `hard_line_group`；
2. `verified=true` 且有非空 provenance；
3. 所有成员存在、同侧、是 scalar muscle channel；
4. hard groups 不重叠；
5. manifest/model/order/hash 全部一致。

当前 checked-in manifest 的 hard group 合法结果是空集合。这是证据边界，
不是缺失实现。

因此所有 IMR loss 在当前资产上恒为 `0.0`。这与"已测量且完全一致"在数值上
无法区分，所以 `intra_muscle_diagnostics` 额外报告 `coverage`：
`measured_group_counts`、`total_measured_group_count` 和
`intra_muscle_measured`。当覆盖为 0 时，`zero_loss_interpretation` 显式写成
`no_group_measured_zero_loss_is_not_evidence_of_consistency`。任何读取 IMR
数字的报告都必须先读 `coverage`。

exact hard-line IMR 与 soft-compartment dispersion 仍是离线报告字段，训练侧
不伪造 `intra_muscle_*` 或 `penalty_intra_muscle`。在线 ABI 现在只增加语义不同的
`fascicle_continuity_*`：它来自显式、非空的局部 adjacency graph，并始终同时
记录 `measured_chain_count` 与 `measured_edge_count`。因此 0 loss 可以区分为
“未测量”或“已测量且无 deadband violation”。总 penalty 同时记录 clip 前值、
clip 后值和单独的 weighted continuity penalty，避免 `-1.0` 下限掩盖该项。

## Portable muscle-channel ABI

bare MyoFullBody 与 jointless rigid-racket 场景共享 354 个身体肌肉通道，但完整
compiled-model hash 不同。taxonomy 和 graph 因而支持两种显式验证模式：

- `exact_runtime_model`：完整场景 hash、package、顺序和每个 actuator 元数据都
  必须一致；
- `portable_muscle_channel_abi`：允许非肌肉场景结构变化，但仍逐通道核对名称、
  顺序、muscle dynamics、`actnum/actadr`、`ctrlrange`、transmission target 与
  dynamics/gain/bias 参数的 core fingerprint。

portable 模式不是关闭模型验证。bare exact 必须通过，racket exact 应因完整模型
hash 改变而失败，racket portable 才通过；任意 ctrlrange、actadr、target 或顺序
篡改仍会失败。

## 局部肌束连续性图与在线模式

checked-in 图位于
`configs/physiology/myofullbody_354_fascicle_continuity_v1.json`，与 curated
taxonomy fingerprint、ordered muscle schema 和 portable core ABI 绑定。第一版只
包含 EO、IO、IL、LTp、Ps 与 MF 的同侧相邻束；明确排除 DELT/PECM/LAT 分区、
biceps/triceps heads、gluteal/adductor compartments、QL 复杂束、左右同名肌肉、
功能性 NMF 分区和 EMG observation aggregate。

主数值对象是 `robust_fascicle_continuity`：对实际
`data.act[actuator_actadr]` 的相邻 edge 绝对差应用 deadband、Huber、chain
normalization 和 stop-gradient activity gate。excitation 可作为独立 command-level
诊断，但不能替代主 activation penalty；synergy coefficient、action、`data.ctrl`
和 actuator force 都不是主连续性信号。

`intra_muscle_consistency.mode` 的合同为：

- `"off"`：不计算、不影响 reward；
- `diagnostics`：计算并记录，强制 `coefficient=0`；
- `reward`：强制正系数、固定两个 fingerprint，并要求 graph 至少有一条带
  provenance 的 verified training chain。

默认 base config 是 `"off"`。诊断 preset 与新 run config 分别是
`forehand_fascicle_continuity_diagnostics_v1.yaml` 和
`conf_fullbody_forehand_clear_early_unified_synergy_v4_continuity_diag.yaml`。
reward preset 使用无默认值的环境变量引用 verified graph/fingerprint/calibrated
coefficient；证据不存在时 Hydra 解析失败，不能误用 checked-in provisional 图。

## 生理—协同联合报告

`analysis/physiology_synergy/build_joint_report.py` 只聚合已有证据，不重新生成
结论。它交叉核对 branch commit、config hash、checkpoint/promotion、taxonomy、
continuity graph、formal W、frozen decoder、EMG mapping、dataset split、session
与 event-reference identity；任一共享 identity 不一致即拒绝输出。报告始终把
task/tracking、control synergy、activation continuity、mapped 15-channel synergy
与 EMG comparison 分开，并写入 claim scope、limitations 和自身 fingerprint。
其中 rollout metrics 不接受裸数字 JSON：必须先用
`build_rollout_metrics_evidence()` 封装为 source-bound artifact，逐项绑定
run/config、checkpoint/promotion、formal W、taxonomy/graph、event/session、
evaluation split 和 environment fingerprint。即使重算外层 hash，跨策略
拼接仍会失败。
联合报告还会重算 resolved `experiment` 的 12 位 config hash，并在 reward 模式下
交叉核对 graph 中的 source/calibration/review fingerprint 与固定系数；不能用一份
自洽但属于另一配置或另一晋级证据的报告拼接结论。

## Phase 3 校准、晋级与 matched ablation

`analysis/physiology_synergy/calibrate_continuity_reward.py` 只消费逐步 held-out
baseline evidence，按 `0.005/0.01/0.02 × median imitation reward` 生成候选预算，
并使用 `q95 activation continuity loss` 得到固定系数。输入必须绑定 run、action
mode、config、checkpoint、promotion、rollout、environment、held-out split、taxonomy
和 source graph；少于 32 步、coverage 为空或 fingerprint 漂移都会失败。

baseline JSON 不需要人工拼接。`fullbody/eval.py` 的
`--continuity_baseline_output_json` 路径会在已恢复 checkpoint 的评估环境中安装
`diagnostics/coefficient=0` 合同，并从每个真实 transition 记录：

- 所有 penalty 之前的 `reward_imitation_total`；
- transition 后 `data.act[actuator_actadr]` 上的 `fascicle_continuity_loss`；
- 实际 chain/edge coverage；
- 显式 trajectory index 与从 0 开始的 step index。

MJX 采集会排除 batch padding lane 与终止后的冻结步；MuJoCo 路径也使用
相同逐步 schema。原始 trajectory/step 坐标和逐步 chain/edge coverage
会保留在落盘 artifact 中，标定时再次验证，而不只信任采集阶段的汇总数。
输出同时绑定 checkpoint 内容、policy promotion artifact、
resolved runtime model、354-channel core ABI、插值后 held-out 轨迹全数组内容、
deterministic seed 和 evaluate-all 协议。若整条轨迹未出现、step 不是从 0 连续前缀、
coverage 与 graph 不同，或任一 manifest hash 漂移，都不会产生标定输入。

实际采集命令必须指向已通过独立 policy promotion 的 checkpoint，例如：

```bash
source configs/env.sh
scripts/run_with_cuda_compat.sh uv run --locked python fullbody/eval.py \
  --path /absolute/path/to/checkpoint_N \
  --metrics --metrics_only --evaluate_all --metrics_deterministic \
  --metrics_envs 8 --eval_seed 0 \
  --continuity_promotion_artifact /absolute/path/to/promoted_stage1.json \
  --continuity_baseline_output_json /absolute/path/to/continuity_baseline.json

uv run --locked python -m analysis.physiology_synergy.calibrate_continuity_reward \
  --baseline-rollout-json /absolute/path/to/continuity_baseline.json \
  --rollout-manifest-json /absolute/path/to/continuity_baseline.json.rollout_manifest.json \
  --selected-budget-fraction 0.01 \
  --output-json /absolute/path/to/continuity_calibration.json
```

第一条命令还会写出 `.rollout_manifest.json` sidecar。这是评估/证据采集，
不是生产训练启动；生产训练仍只能使用 `scripts/run_fullbody_training.sh`。

`analysis/physiology_synergy/promote_continuity_chains.py` 不会覆盖 provisional source
graph。第一批只接受 canonical EO/IO 左右四条链，并要求 exact topology、同侧、
相邻层级、baseline distribution、deadband data support 和 training approval 全部由
独立审核者显式确认。晋级 graph 会绑定 calibration/review/source graph，其他 24 条
链仍保持 provisional、diagnostics-only。

`fullbody/config_specific_task/stage1_body/continuity_ablation_v1/` 固化 A0/A1、
B0/B1、C0/C1、G0/G1 × seeds 0/1/2 共 24 个 run。所有 run 使用唯一 run ID、
`auto_resume=false`、`resume_from=null` 和 fresh optimizer。reward/graph preset 的证据
变量没有可用默认值，因此缺少正式 artifact 时 Hydra 或 action/reward loader 会失败，
不会回退到 checked-in provisional graph。结果只能由
`build_continuity_ablation_report.py` 从完整 24-run、同 seed、同非 reward 合同的证据
生成；每个 rewarded run 必须精确等于已绑定 calibration 的固定系数，
B/G 对还必须声明除 basis 拟合外完全一致的合同 fingerprint。证据必须
同时包含 continuity coverage、activation/excitation continuity、control clipping/能量、
synergy/residual 使用和性能开销，并为每个 run 绑定完整 joint-report fingerprint。
任务退化但 continuity 改善时必须标为 Pareto trade-off。

## Phase 4 Graph-NMF

`musclemimic.synergy.graph_nmf` 将 verified training edges 编译为与 ordered 354
通道对齐的对称 adjacency。`fit_nmf` 的正 `graph_lambda` 路径实现
`C` 的标准更新和 `B` 的 Laplacian multiplicative update；`graph_lambda=0` 不接收
adjacency，并保持原始实现的 bitwise 回归路径。第一版只允许 source signal units、
`normalization=none`，basis artifact 加载时会再次核对 unit scales 和 ordered-muscle
hash，防止把 graph lineage 附到通道缩放或重排后的 W 上。

Graph-NMF 与 online reward 是两个独立因素。标准 action preset 明确禁止 graph
artifact，graph action preset则要求 basis、coefficient stats、graph lineage、source
graph fingerprint 和 lambda 全部固定。任何 graph W 都必须重新完成 rank selection、
稳定性、dynamic coverage、coefficient statistics、frozen decoder 与后续训练，不能给
旧 W manifest 补字段后冒充新拟合。

## 协同与 taxonomy 的顺序绑定

synergy 与 anatomy 各自锁定自己的通道顺序，但字段名不同：synergy 侧是
`muscle_schema_sha256`（basis artifact）或 `ordered_muscle_schema_sha256`
（regional grouping），anatomy 侧是 `actuator_schema_hash` 加
`runtime_model_hash`。两者各自自洽，所以一份在某个通道顺序上拟合的 basis
与一份从另一个模型导出的 taxonomy 可以分别通过校验，却对"第 k 个通道是哪块
肌肉"给出不同答案。IMR 完全按位置索引成员，这种分歧不会报错，只会把每个
group 的成员静默换成别的肌肉。

`musclemimic.physiology.synergy_binding` 提供缺失的交叉校验：

- `taxonomy_ordered_muscle_schema_hash`：用 synergy 的规范化方式
  （`{"muscle_names": [...]}` 的 canonical JSON + sha256，两侧逐字节相同）
  哈希 taxonomy 的 ordered actuator 名；
- `assert_taxonomy_matches_ordered_muscles`：逐元素比较并在不一致时报出
  第一个分歧下标，而不是只给一个哈希差异；
- `assert_synergy_artifact_matches_taxonomy`：绑定 artifact 声明的哈希。
  `grouping_class` 用白名单而非黑名单：只接受 `functional_synergy_region`
  （大小写不敏感）。原因是 taxonomy 自己的顶层键是复数
  （`hard_line_groups`、`observation_aggregates`……），`build_intra_muscle_spec`
  也用复数，所以最可能的误标就是照抄这些复数键——只列举单数拼写的黑名单会
  把它们全部放过去。

`ordered_muscle_schema_sha256` 在本模块内重述那段 canonical JSON，而不是从
`musclemimic.synergy.grouping` 导入。这样本模块只依赖标准库，synergy 侧才能
反向调用 physiology 做交叉校验而不形成 import 循环；两侧（以及
`basis_artifact._json_sha256`）逐字节一致这一点由测试断言，不再是两处独立
`json.dumps` 的巧合。

生效路径（不是只有 API，而是有真实调用者）：

- `build_physiology_report` 在同时给出 taxonomy 和 `synergy_reconstruction` 时
  调用 `assert_taxonomy_matches_ordered_muscles`，结果记在
  `synergy_residual.taxonomy_binding`；
- `stage3_signal_export` 现在把导出通道的 `ordered_muscle_schema_sha256` 写进
  NPZ，所以上面那条校验有了真实生产者，不再恒走
  `unverified_synergy_lineage` 分支；输入确实没有声明任何 synergy 哈希时才记
  `unverified_synergy_lineage`，而不是当作已核验；
- `load_grouping_json(..., taxonomy=...)` 调用
  `assert_synergy_artifact_matches_taxonomy`；`synergy.fit` 的
  `--anatomical-taxonomy-json` 把它接到 regional 拟合上，并在 manifest 里记
  `grouping_bound_to_anatomical_taxonomy`。不传 taxonomy 时行为不变（仍只对
  数据集顺序自洽），这是为了不改变既有 run 的语义；
- `scripts/export_myofullbody_muscle_taxonomy.py` 导出时回调
  `validate_taxonomy_against_model`，把 manifest 绑回它所导出的那个模型，避免

## 两种 IMR 定义

`musclemimic.physiology.intra_muscle` 同时保留：

- exact Exo variant：用于论文可比的复现诊断；
- robust project variant：deadband excess、Huber、activity gate 和
  group normalization，用于后续 matched ablation。

后者是本项目设计，不能表述为 Exo-Plore 原公式。论文中的 deadband `0.1`
和权重 `0.1` 来自 DART/MCN 监督学习尺度，不能直接复制为 PPO reward
超参数。任何 reward 接入都必须在 Phase 1 诊断后另行提交，并保留同 seed、
无 IMR baseline。

## 证据等级

以下事实由一手来源直接支持：

- MuJoCo muscle dynamics 对 control 内部钳制到 `[0,1]`，activation 是
  control 的一阶动态状态；见
  [MuJoCo 3.4.0 muscle 文档](https://mujoco.readthedocs.io/en/3.4.0/modeling.html#muscles)
  和
  [XML reference](https://mujoco.readthedocs.io/en/3.4.0/XMLreference.html#actuator-muscle)；
- Exo-Plore 的原始 IMR 约束 numerical line muscles，但其 MCN/DART
  设置不等价于本仓库的 MuJoCo PPO；见
  [Exo-Plore](https://arxiv.org/abs/2601.22550)；
- 所引肩部模型和快速等长任务分别显示了 compartment 的不同机械路径与
  方向相关招募，支持“不要按共享前缀硬等同”；见
  [Holzbaur et al. 2005](https://pubmed.ncbi.nlm.nih.gov/16078622/)
  与
  [Brown et al. 2007](https://pubmed.ncbi.nlm.nih.gov/16458022/)；
- NMF 是非负 synergy 的合理 baseline，但 VAF 不能单独证明 neural
  modules；见
  [Rabbi et al. 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7237673/)；
- SENIAM 规范电极布置而不提供 actuator→sEMG 真值映射；见
  [SENIAM](https://www.seniam.org/) 和
  [Hermens et al. 2000](https://pubmed.ncbi.nlm.nih.gov/11018445/)。

Huber/activity gate/curriculum、moment-arm 阈值、16-to-15 observation projection、
bootstrap/Hungarian stability gate 都仍是待验证的项目方法，不应写成这些
来源已经证明的结论。
