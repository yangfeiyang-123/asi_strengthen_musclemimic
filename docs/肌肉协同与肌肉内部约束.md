## 0. 先给结论

### 0.1 当前最优先的事情不是立即加入 IMR loss，而是修正肌肉控制信号语义

当前代码把所有 MuJoCo muscle actuator 的 `ctrlrange` 强制设为 `[-1, 1]`，同时又使用
$$
e_{\mathrm{declared}}
=
\frac{\mathrm{ctrl}-\mathrm{low}}{\mathrm{high}-\mathrm{low}}
=
\frac{\mathrm{ctrl}+1}{2}
$$
把原始 `data.ctrl` 转成所谓的 `[0,1]` “physical excitation”。

但 MuJoCo 的原生 muscle activation dynamics 会在内部把输入 `ctrl` 截断到 `[0,1]`。所以实际进入肌肉激活动力学的信号是：
$$
e_{\mathrm{effective}}
=
\operatorname{clip}(\mathrm{ctrl},0,1)
$$
这两个信号不是一回事。

在当前 signed control range 下，协同解码器给出的期望 excitation $e$ 经现有动作链后变为：
$$
e
\rightarrow
a_{\mathrm{body}}=2e-1
\rightarrow
\mathrm{ctrl}=2e-1
\rightarrow
e_{\mathrm{effective}}=\operatorname{clip}(2e-1,0,1)
$$
因此：

| 协同解码器声明的 $e$ | 354 维 normalized body action | `data.ctrl` | MuJoCo 实际输入 |
|---:|---:|---:|---:|
| 0.00 | -1.00 | -1.00 | 0.00 |
| 0.25 | -0.50 | -0.50 | 0.00 |
| 0.50 | 0.00 | 0.00 | 0.00 |
| 0.75 | 0.50 | 0.50 | 0.50 |
| 1.00 | 1.00 | 1.00 | 1.00 |

也就是说，**协同解码器输出的前半段 $e\in[0,0.5]$ 在实际物理中全部塌缩为零激活输入**。与此同时，数据集仍把这些值记录成 0 到 0.5 的“excitation”。这会影响：

- 基于 excitation 的 NMF 协同提取；
- fixed synergy decoder 的物理意义；
- residual synergy 的有效控制范围；
- full-354 与 synergy 的探索噪声标定；
- excitation energy、饱和率和协同诊断；
- 以后加入的 excitation-level 肌肉内部一致性；
- 对“低维协同控制具有生理意义”的论文表述。

**因此，P0 阻塞项是：先统一 policy action、raw ctrl、effective excitation 和 activation 的语义。**

---

### 0.2 “肌肉内部一致性”不能直接按照名字前缀自动分组

Exo-Plore 中的 IMR 假设是：同一块解剖肌肉被模型拆成多条 line muscle，而人不能独立控制这些计算线段，因此这些线段的 activation 不应过度分裂。

MyoFullBody 的 354 个 actuator 中，很多编号并不是“同一神经驱动的重复线段”，而是：

- 三角肌前、中、后束；
- 胸大肌不同部位；
- 背阔肌不同部位；
- 肱二头肌长头与短头；
- 肱三头肌长头、外侧头、内侧头；
- 臀肌不同功能分区；
- 躯干肌在不同椎体水平的节段或肌束。

这些部分可能具有不同力臂、功能和募集时序。把它们强制相等会损害正手高远球所需的快速、方向特异的肩—躯干控制。

因此，建议把分组分成四类：

1. **hard line group**：确实是同一神经肌肉单元的数值离散线段；可加入较强一致性；
2. **soft compartment group**：同一广义解剖肌肉的不同分区；只能施加很弱的软一致性或图平滑；
3. **observation aggregate**：多个模型 actuator 映射到一个表面 EMG 通道；只用于评估，不用于强制相等；
4. **functional synergy region**：当前 NMF 的跨肌肉功能区域；用于协同提取，绝不能当作“肌肉内部组”。

一个科学上诚实的第一版，很可能只有很少、甚至暂时没有 `hard line group`。这并不意味着模块没价值：可以先完成完整审计、只记录 diagnostics，再逐步开放经过验证的组。

---

### 0.3 最推荐的统一研究故事

你的项目可以形成三层生理合理性框架：
$$
\boxed{
\text{line-element consistency}
\rightarrow
\text{anatomical-muscle recruitment}
\rightarrow
\text{multi-muscle synergy}
}
$$
- **第 1 层：肌肉内部一致性**  
  判断同一已验证解剖/神经单元的多条模型执行器是否异常分裂。
- **第 2 层：解剖肌肉/EMG 通道映射**  
  保留 16 个实测通道，并把 354 个 actuator 的真实 activation 投影到
  15 个有已知模型候选的可比通道；S1 不被静默删除或猜测映射。
- **第 3 层：肌肉协同**  
  比较真人与仿真在不同肌肉之间的低维协同结构和时序。

核心原则是：

> IMR 约束局部冗余解；NMF 描述跨肌肉协同；EMG 映射是观测模型。三者不能混成一个分组表。

## 2. P0：先修正 muscle excitation 的物理语义

### 2.1 问题所在文件

主要涉及：

- `musclemimic/environments/humanoids/myofullbody.py`
- `loco_mujoco/core/control_functions/default.py`
- `musclemimic/distill/physical.py`
- `musclemimic/synergy/action_interface.py`
- `musclemimic/synergy/frozen_decoder.py`
- `musclemimic/algorithms/common/env_utils.py`
- `tests/unit/test_physical_distill_contract.py`

`MyoFullBody._apply_spec_changes` 当前把 muscle actuator 控制范围改成 `[-1,1]`。  
`DefaultControl` 又把策略的 normalized `[-1,1]` 线性映射到 actuator control range。  
`physical_ctrl_to_unit_excitation` 则按 actuator range 做仿射归一化。

单看每个模块都像是合理的，但与 MuJoCo muscle dynamics 的内部 `[0,1]` clamp 组合后产生了语义错误。

### 2.2 推荐修复：恢复 muscle actuator 的物理 `ctrlrange=[0,1]`

保留策略接口为 `[-1,1]`，只修改底层 actuator range：

```python
# musclemimic/environments/humanoids/myofullbody.py

for actuator in spec.actuators:
    if actuator.dyntype == mujoco.mjtDyn.mjDYN_MUSCLE:
        actuator.ctrlrange = [0.0, 1.0]
        actuator.ctrllimited = True
```

此时：
$$
a_{\mathrm{policy}}\in[-1,1]
$$
经 `DefaultControl` 后：
$$
\mathrm{ctrl}
=
0.5(a_{\mathrm{policy}}+1)
\in[0,1]
$$
协同解码器若输出期望 excitation $e$，继续使用：
$$
a_{\mathrm{body}}=2e-1
$$
则：
$$
a_{\mathrm{body}}
\rightarrow
\mathrm{ctrl}=e
\rightarrow
e_{\mathrm{effective}}=e
$$
整个链路变为一一对应。

### 2.3 不推荐但可行的替代方案：保留 signed ctrlrange，显式定义有效 excitation

若由于旧 checkpoint ABI 必须保留 `[-1,1]`，则必须承认：
$$
e_{\mathrm{effective}}=\operatorname{clip}(\mathrm{ctrl},0,1)
$$
并重写 inverse mapping，使期望 $e$ 直接映射为 raw ctrl $e$，而不是 $2e-1$。

这会使底层物理 ctrl 与 actuator 声明范围只使用 `[0,1]` 的一半，动作 ABI 更绕，探索噪声也具有非对称边界。长期维护价值低于直接恢复 `[0,1]`。

### 2.4 必须升级信号 schema

建议在 `musclemimic/distill/physical.py` 中引入新契约：

```python
EFFECTIVE_MUSCLE_EXCITATION_V2 = {
    "schema_version": "effective_mujoco_muscle_excitation_v2",
    "source": "transition_state.data.ctrl",
    "formula": "clip(raw_ctrl, 0, 1) for MuJoCo muscle actuators",
    "range": [0.0, 1.0],
}
```

并明确废弃或重命名旧信号：

```text
unit_excitation_from_declared_ctrlrange_v1
```

旧信号不是“MuJoCo 实际 excitation”，只能称为“ctrlrange-normalized command coordinate”。

### 2.5 数据与 basis 迁移

现有 distillation shard 已保存 `teacher_ctrl_physical`，因此通常不需要完全丢弃旧数据。

建议写迁移脚本：

```python
raw_ctrl = shard["teacher_ctrl_physical"]
effective_excitation = np.clip(raw_ctrl, 0.0, 1.0)

# 仅对被验证为 MuJoCo muscle actuator 的通道执行。
# 非 muscle actuator 必须按其自身控制语义处理。
```

迁移流程：

1. 读取旧 metadata 的 actuator 名称、顺序、`ctrlrange` 和 model hash；
2. 验证每个目标通道是 `mjDYN_MUSCLE`；
3. 从 `teacher_ctrl_physical` 重算 `effective_excitation`；
4. 保留原始字段，但新增 v2 字段和迁移 provenance；
5. 重新拟合所有以 excitation 为源的 NMF basis；
6. 重新生成 coefficient statistics、hybrid basis 和 frozen decoder；
7. 对以 `data.act` 为源的 basis 做重新验证；其值本身没有被错误仿射映射，但旧策略的控制死区会影响其数据分布；
8. 禁止新代码静默加载 v1 excitation basis。

### 2.6 checkpoint 兼容性

将 actuator range 从 `[-1,1]` 改为 `[0,1]` 后，旧 full-354 checkpoint 不能直接加载：

- 旧环境中 policy action 0 对应 raw ctrl 0；
- 新环境中 policy action 0 对应 raw ctrl 0.5。

若仅为了复现实验，可增加兼容适配器：
$$
a_{\mathrm{new}}
=
2\operatorname{clip}(a_{\mathrm{old}},0,1)-1
$$
它使新环境中的 raw ctrl 接近旧环境的有效 excitation。但它是非线性、不可逆的，只适合兼容评估，不应成为新训练的长期接口。

### 2.7 必须新增的端到端单测

```python
@pytest.mark.parametrize("desired", [0.0, 0.1, 0.5, 0.9, 1.0])
def test_desired_excitation_reaches_mujoco_muscle_input(desired):
    body_action = 2.0 * desired - 1.0
    raw_ctrl = default_control(body_action, actuator_range=(0.0, 1.0))
    effective = np.clip(raw_ctrl, 0.0, 1.0)
    assert effective == pytest.approx(desired)
```

还要测试 full-354 与 synergy 在给定相同 354 维期望 excitation 时得到相同：

- raw ctrl；
- effective excitation；
- one-step activation；
- one-step actuator force。

## 3. “肌肉内部一致性”到底应该约束什么

### 3.1 Exo-Plore 的 IMR

Exo-Plore 的形式为：
$$
L_{\mathrm{IMR}}
=
\sum_g
\sum_{j\in G_g}
\mathbf{1}
\left(
|a_j-\bar a_g|>0.1
\right)
(a_j-\bar a_g)^2
$$
$$
\bar a_g
=
\frac{1}{|G_g|}
\sum_{j\in G_g}a_j
$$
它的作用是：同一解剖肌肉被离散为多条 line muscle 时，防止网络只激活其中一条、其余几乎关闭。

论文使用的 `0.1` deadband 和 `w_IMR=0.1` 是针对其模型、MCN 损失尺度和步态任务得到的超参数，不能直接照搬到你的 PPO reward。

### 3.2 对你的项目更准确的定义

对第 $g$ 个经过验证的组，设成员 activation 为 $a_i$，成员权重为 $w_i$：
$$
\mu_g
=
\frac{\sum_{i\in G_g}w_i a_i}
{\sum_{i\in G_g}w_i}
$$
定义 deadband excess：
$$
d_i
=
\max\left(
|a_i-\mu_g|-\delta_g,\ 0
\right)
$$
定义活动门控：
$$
q_g
=
\operatorname{stopgrad}
\left[
\operatorname{clip}
\left(
\frac{\mu_g-a_{\mathrm{off}}}
{a_{\mathrm{on}}-a_{\mathrm{off}}},
0,1
\right)
\right]
$$
再使用 robust group loss：
$$
L_g
=
q_g
\cdot
\frac{
\sum_{i\in G_g}w_i\,
\operatorname{Huber}(d_i/s_g)
}{
\sum_{i\in G_g}w_i
}
$$
总损失：
$$
L_{\mathrm{intra}}
=
\frac{
\sum_g \lambda_g L_g
}{
\sum_g \lambda_g q_g+\epsilon
}
$$
这样做比原论文的硬指示函数更适合 JAX/PPO：

- deadband 附近连续；
- 不活跃肌肉组不会因为数值噪声被罚；
- 每组先归一化，避免成员多的组支配总损失；
- 可分别设置 hard group 与 soft group 权重；
- Huber 降低偶发数值尖峰对 PPO 的破坏。

### 3.3 应优先约束 activation，而不是 force

首选：
$$
L_{\mathrm{intra}}^{a}
=
L_{\mathrm{intra}}(\mathrm{data.act})
$$
原因：

- activation 更接近神经驱动经过激活动力学后的状态；
- 同一神经驱动的不同 line element 可以有不同最大力、长度、速度和力臂；
- 即使 activation 相同，force 也可能不同，这是正常现象；
- 对 force 做相等约束会破坏多路径肌肉模型的物理意义。

可以另外记录命令级诊断：
$$
L_{\mathrm{intra}}^{e}
=
L_{\mathrm{intra}}(e_{\mathrm{effective}})
$$
但论文中的主要“生理合理性”结论应以 activation 为主。

## 4. 肌肉分组不能只靠名称：建议建立四层 taxonomy

### 4.1 四类关系

#### A. `hard_line_group`

满足以下条件时才启用强约束：

- 同一侧；
- 模型文档明确说明是同一肌肉的多条数值作用线；
- 共享相同或等价的神经 activation 输入；
- activation dynamics 参数一致；
- 在采样姿态中力臂方向高度一致；
- 不代表不同头、不同肌束或不同解剖分区。

#### B. `soft_compartment_group`

同一广义肌肉，但不同分区有独立功能，例如：

- `DELT1/DELT2/DELT3`
- `PECM1/PECM2/PECM3`
- `LAT1/LAT2/LAT3`
- `glmed1/glmed2/glmed3`

它们最多使用很小的软正则或相邻图平滑，不应强制相等。

#### C. `observation_aggregate`

用于把模型信号映射到一个表面 EMG 通道。例如当前模板：

- `BIClong + BICshort -> biceps_brachii`
- `TRIlong + TRIlat + TRImed -> triceps_brachii`
- `FCR + FCU -> wrist_flexor_group`

这是电极观测模型，不代表这些 actuator 应具有相同 activation。

#### D. `functional_synergy_region`

当前：

`experiments/synergy/forehand_clear_myofullbody_354_regions_v1.json`

定义的：

- pelvis/trunk
- right shoulder/upper arm
- right elbow/forearm
- right wrist
- left arm
- right lower limb
- left lower limb

是 NMF 分区和 rank allocation 结构。它包含大量不同解剖肌肉，不能用于 IMR。

## 5. 当前 354 actuator 的生理解剖分组指导

### 5.1 右上肢高置信度分类

### 5.3 躯干肌

`Ps_*`、`MF_*`、`EO*`、`IO*` 等名称常包含椎体水平、附着点或肌束编号。它们可能表示节段性控制而不是同一输入的重复数值线。

对躯干建议使用：
$$
L_{\mathrm{adjacent}}
=
\sum_{(i,j)\in E}
\omega_{ij}(a_i-a_j)^2
$$
其中 $E$ 只连接相邻椎体水平，且权重很小。它应称为：

```text
segmental activation smoothness
```

而不是“同一肌肉 line 一致性”。

### 5.4 第一版分组的诚实策略

第一版配置建议：

- `hard_line_group`: 只收录模型作者或原始资产文档明确确认的组；
- 如果目前没有足够证据，允许为空；
- `soft_compartment_group`: 可以收录 DELT、PECM、LAT、gluteal subdivisions，但默认 `loss_enabled=false`，只记录指标；
- `observation_aggregate`: 显式记录 16 个实测通道，其中 15 个可比、
  1 个因无已核验模型同源物而排除；
- `functional_synergy_region`: 继续使用现有 NMF grouping，不与 anatomy manifest 合并。


输出每个 actuator：

- ordered index；
- name；
- side；
- actuator type / `dyntype`；
- `actadr`、`actnum`；
- ctrlrange；
- activation time constants；
- tendon name；
- source asset；
-最大力或对应的 muscle force parameter；
- 所跨越的 joint/DOF；
- 多个参考姿态下的 moment-arm vector；
- 候选名称 family；
- model package version；
- model binary hash；

### 6.2 moment-arm 审计

在若干合法姿态 $q^{(p)}$ 下运行 `mj_forward`，读取：
$$
R_i^{(p)}
=
\mathrm{data.actuator\_moment}[i,:]
$$
对候选成员 $i,j$ 计算：
$$
s_{ij}
=
\operatorname{median}_p
\frac{
R_i^{(p)}\cdot R_j^{(p)}
}{
\|R_i^{(p)}\|\|R_j^{(p)}\|+\epsilon
}
$$
可使用以下筛选，仅作为候选证据：

- `median cosine > 0.95`
- 作用 DOF 符号一致；
- moment-arm magnitude ratio 在姿态间稳定；
- activation dynamics 参数一致；
- 同一侧、同一模型来源；
- 文档说明它们属于同一神经肌肉单元。

高 moment-arm 相似度仍不能证明共享神经驱动，因此自动程序只能生成 `provisional`，不能自动启用 loss。

### 8.4 一致性损失

```python
from typing import NamedTuple
import jax
import jax.numpy as jnp


class IntraMetrics(NamedTuple):
    loss: jax.Array
    active_group_fraction: jax.Array
    violation_fraction: jax.Array
    mean_abs_deviation: jax.Array
    max_abs_deviation: jax.Array


def _huber(x: jax.Array, delta: float = 1.0) -> jax.Array:
    ax = jnp.abs(x)
    quadratic = jnp.minimum(ax, delta)
    linear = ax - quadratic
    return 0.5 * quadratic**2 + delta * linear


def intra_muscle_consistency(
    ordered_signal: jax.Array,
    spec: IntraMuscleSpec,
    *,
    scale: float = 0.05,
    eps: float = 1e-8,
) -> IntraMetrics:
    values = ordered_signal[spec.group_indices]  # [G, L]

    weights = spec.member_weights * spec.member_mask
    weight_sum = jnp.maximum(jnp.sum(weights, axis=-1), eps)

    mean = jnp.sum(weights * values, axis=-1) / weight_sum
    abs_dev = jnp.abs(values - mean[:, None])

    excess = jax.nn.relu(abs_dev - spec.deadband[:, None])
    element_loss = _huber(excess / scale)

    group_loss = jnp.sum(weights * element_loss, axis=-1) / weight_sum

    denom = jnp.maximum(spec.activity_on - spec.activity_off, eps)
    activity_gate = jnp.clip(
        (mean - spec.activity_off) / denom,
        0.0,
        1.0,
    )
    activity_gate = jax.lax.stop_gradient(activity_gate)

    effective_group_weight = spec.group_weights * activity_gate
    total_weight = jnp.maximum(jnp.sum(effective_group_weight), eps)
    total_loss = jnp.sum(effective_group_weight * group_loss) / total_weight

    valid_member_count = jnp.maximum(jnp.sum(spec.member_mask), 1.0)
    violation_fraction = (
        jnp.sum(spec.member_mask * (excess > 0.0))
        / valid_member_count
    )

    return IntraMetrics(
        loss=total_loss,
        active_group_fraction=jnp.mean(activity_gate > 0.0),
        violation_fraction=violation_fraction,
        mean_abs_deviation=(
            jnp.sum(spec.member_mask * abs_dev) / valid_member_count
        ),
        max_abs_deviation=jnp.max(
            jnp.where(spec.member_mask > 0, abs_dev, 0.0)
        ),
    )
```

### 8.5 member weights 怎么选

- **hard line group 的 activation 一致性**：默认等权最容易解释，因为若共享神经驱动，各线段 activation 应接近；
- 若数值离散线的 PCSA/Fmax 极不均衡，可做 weighted mean，但必须在 manifest 中记录来源；
- **EMG 通道聚合**：可用 PCSA/Fmax、解剖体积或经过标定的观测权重；
- 不要用 EMG mapping 权重直接替代 hard consistency 权重。

## 10. command-level consistency 如何接入 synergy decoder

### 10.1 约束位置

如果 residual 开启：
$$
e_{\mathrm{preclip}}
=
b + Wc + R\rho
$$
$$
e_{\mathrm{decoded}}
=
\operatorname{clip}(e_{\mathrm{preclip}},0,1)
$$
建议记录两个版本：

- `preclip_intra_loss`：发现 residual 在 clip 前造成的异常分裂；
- `decoded_intra_loss`：实际命令边界内的一致性。

训练 reward 首选 actual activation；command-level loss 只作为辅助，且必须在 P0 语义修复后使用。

### 10.2 为什么不能只看 clip 后结果

例如一个组的 preclip 输出：
$$
[1.8,\ 0.9,\ 0.8]
$$
clip 后变为：
$$
[1.0,\ 0.9,\ 0.8]
$$
差异被显著掩盖。若 residual 经常依靠饱和隐藏不一致，策略可能具有较差的可迁移性和梯度条件。

### 10.3 wrapper 与 reward 的推荐职责

- `SynergyActionWrapper`：继续负责解码和 decoder diagnostics；
- 基础环境 reward：负责 `data.ctrl` / `data.act` 的实际生理 penalty；
- 不要在 wrapper 中重复减 reward，避免 autoreset、transition state 和日志 ABI 出现两套权威；
- 若需要 preclip metric，由 wrapper 写入 `info`，仅作为诊断或由统一 reward adaptor 显式消费。

## 11. 肌肉协同与肌肉内部一致性的合理组合

### 11.1 两者的数学对象不同

肌肉内部一致性：
$$
L_{\mathrm{intra}}(a)
$$
约束少量已验证的局部成员。

肌肉协同：
$$
A \approx WH
$$
其中：

- $A\in\mathbb{R}_{+}^{M\times T}$：多个不同肌肉的时序；
- $W\in\mathbb{R}_{+}^{M\times K}$：协同结构；
- $H\in\mathbb{R}_{+}^{K\times T}$：协同激活时序。

前者是局部结构先验，后者是跨肌肉低维表示。

### 11.2 推荐统一流程

```text
low-dimensional policy
        |
        v
synergy decoder Wc + residual
        |
        v
corrected effective excitation, 354
        |
        v
MuJoCo activation dynamics
        |
        v
actual activation, 354
        |
        |-- intra-muscle consistency diagnostics/reward
        |
        v
anatomical / EMG observation projection
        |
        v
15-channel simulated signal
        |
        v
NMF synergy comparison with real sEMG
```

### 11.3 训练阶段

推荐损失/奖励：
$$
r
=
r_{\mathrm{motion}}
+
r_{\mathrm{task}}
-
\lambda_{\mathrm{effort}}L_{\mathrm{effort}}
-
\lambda_{\mathrm{intra}}L_{\mathrm{intra}}^{a}
-
\lambda_{\mathrm{smooth}}L_{\mathrm{smooth}}
$$
第一阶段不要把真人 NMF basis 直接强制进 PPO。

原因：

- sEMG 与仿真 activation 不是同一物理量；
- 15 通道只覆盖 354 actuator 的一小部分；
- 电极位置、串扰和 MVC 归一化会改变幅值；
- 固定真实协同可能限制高速击球中的个体策略；
- 你需要先证明不使用 EMG 监督时，模型仍能恢复合理协同。

### 11.4 后验验证阶段

从真实数据得到：
$$
A_{\mathrm{EMG}}\approx W_{\mathrm{EMG}}H_{\mathrm{EMG}}
$$
从仿真映射后的 15 通道得到：
$$
A_{\mathrm{sim15}}\approx W_{\mathrm{sim}}H_{\mathrm{sim}}
$$
使用 Hungarian matching 对齐协同列，再比较：

- 协同数量 $K$；
- global VAF；
- per-channel VAF；
- $W$ cosine similarity；
- $H$ correlation；
- onset、peak、offset 误差；
- impact 前后积分；
- 不同动作间 shared synergy；
- 不同被试、seed 和 trial 稳定性。

### 11.5 后续可选的弱监督

只有在后验结果稳定后，才考虑：
$$
L_{\mathrm{EMG-subspace}}
=
\left\|
A_{\mathrm{sim15}}
-
W_{\mathrm{EMG}}
H_{\mathrm{sim}}^\*
\right\|_F^2
$$
其中：
$$
H_{\mathrm{sim}}^\*
=
\arg\min_{H\ge0}
\|A_{\mathrm{sim15}}-W_{\mathrm{EMG}}H\|_F^2
$$
这约束的是仿真信号落在真人协同子空间附近，而不是逐采样点复制 EMG。

```json
  "simulation_actuators": ["DELT1"],
  "weights": [1.0],
  "signal_source": "mujoco_activation",
  "side": "right",
  "normalization": "mvc",
  "electrode_protocol": "documented_protocol_id",
  "mapping_confidence": "high",
  "mapping_uncertainty": "surface EMG approximates one compartment"
}
```

对于多 actuator 聚合：
$$
y_c(t)
=
\sum_i P_{ci}a_i(t)
$$
其中 $P$ 是 observation projection matrix。

必须强调：

> $P$ 只描述“电极看到了什么”，不表示 $P$ 中的 actuator 必须在训练时相等。

例如 biceps 表面电极不能可靠分离长头和短头，不等于长头和短头在所有羽毛球阶段都应相同。

## 13. 建议的 NMF 实验设计

当前 active profile 有 16 个传感器，但仿真对比仅使用其中 15 个。
实际动作数与合格 trial 数以 importer 审计报告为准，不再假设“每类 15 次”。

### 13.1 数据切分

按 trial 或被试切分，禁止随机打散时间帧：

- train：拟合 basis；
- validation：选 rank 和超参数；
- test：最终报告。

若只有一个被试，至少使用 leave-trial-out。若有多个被试，优先 leave-subject-out 或 subject-specific + group-level 两套分析。

### 13.2 时间对齐

优先使用事件：

- preparation onset；
- acceleration onset；
- impact；
- follow-through endpoint。

不要只按序列长度线性拉伸而忽略击球事件。

### 13.3 rank 选择

不能只看 global VAF。建议同时要求：

- global VAF；
- 10% 分位数 local/channel VAF；
- split-half stability；
- bootstrap stability；
- cross-trial stability；
- basis condition number；
- 最小有效 rank fraction。

你的仓库已有大量这些 gate，可以继续复用。

### 13.4 比较对象

至少比较：

1. 真人 15 通道；
2. full-354 policy 映射到 15 通道；
3. fixed synergy policy 映射到 15 通道；
4. fixed synergy + intra consistency；
5. full-354 + intra consistency；
6. 可选 residual synergy。

这样能够区分：

- 低维 action space 本身的作用；
- IMR 的作用；
- 二者是否互补；
- 是否改善生理指标但损害轨迹跟踪。

## 14.1 P0——已确认、必须在正式训练前修复

- `distill/physical.py`

- exploration RMS calibration 错误；
- 加 IMR 后会在错误信号上进行优化；
- full-354 与 synergy 的生理比较失真。

**修复**

优先将 muscle actuator range 恢复为 `[0,1]`，升级 schema，并迁移 basis/checkpoint。

## 14.2 P1——已确认的高优先级问题

### Bug P1-1：外部模型资产没有精确版本锁定

`pyproject.toml` 使用：

```text
musclemimic_models>=1.0.2
```

但 PR #1 的多个契约依赖：

- 精确 354 actuator 顺序；
- exact schema hash；
- hardcoded finger actuator names；
- exact model binary hash；
- grouping boundary names。

只要依赖升级，actuator 顺序、参数或 XML 都可能变化。

**修复**

```toml
musclemimic_models==1.0.5
```

或直接锁定可验证的 source commit，并把版本与 commit 写入：

- checkpoint metadata；
- basis artifact；
- anatomy manifest；
- evaluation report。

### Bug P1-2：现有单测把错误 excitation 语义写成“正确答案”

`tests/unit/test_physical_distill_contract.py` 明确断言：
$$
e=0.5(a_{\mathrm{normalized}}+1)
$$
即使 actuator range 是 `[-1,1]`。

因此 CI 可以全部通过，但测试的是“声明 ctrlrange 的仿射坐标”，不是 MuJoCo muscle dynamics 的实际输入。

**修复**

增加 actuator type-aware semantics，并用 end-to-end MuJoCo step 测试。

### Bug P1-3：full-354 exploration calibration 假设对任何 ctrlrange 都有固定导数 0.5

`env_utils.py` 中的注释和计算假设：
$$
\frac{\partial e}{\partial a}=0.5
$$
与 ctrlrange 无关。

对于 signed muscle ctrlrange 与 MuJoCo clamp 的组合，实际映射是分段的：
$$
\frac{\partial e_{\mathrm{effective}}}{\partial a}
=
\begin{cases}
0,&a<0\\
1,&0<a<1
\end{cases}
$$
所以当前 `target_initial_excitation_rms` 不是真实物理 RMS。

**修复**

在 `[0,1]` actuator range 修复后，0.5 仿射导数才重新成立。

### Bug P1-4：`MetricsHandler` 保存了 `_trajectory_handler`，但仍读取未初始化的 `_traj_data`

`musclemimic/utils/metrics.py` 中：

```python
self._trajectory_handler = env.th if env.th is not None else None
```

但随后：

```python
assert self._traj_data is not None
```

并且 frame coverage、root offset 等处继续访问 `self._traj_data`。构造函数中没有给它赋值。

结果：

- `validation.measures` 非空时可能在初始化直接 `AttributeError`；
- 即使 measures 为空，调用 `__call__` 计算 frame coverage 时也可能报错；
- 现有 `tests/unit/test_metrics.py` 多数通过 `object.__new__(MetricsHandler)` 绕过重型 `__init__`，因此没有覆盖这个错误。

**修复方式之一**

```python
self._trajectory_handler = env.th if env.th is not None else None
self._traj_data = (
    None
    if self._trajectory_handler is None
    else self._trajectory_handler.traj.data
)
```

更稳妥的是只保留 handler，并用 property：

```python
@property
def _traj_data(self):
    if self._trajectory_handler is None:
        return None
    return self._trajectory_handler.traj.data
```

同时增加一个真正调用 `MetricsHandler(config, env)` 的构造单测。

## 14.3 P1/P2——高风险潜在问题，需要运行时确认

### Risk P1-5：finger tendon 删除使用 substring，短名称可能误删

`remove_finger_dofs` 对 joint 和 actuator 使用 exact match，但对 tendon 使用：

```python
if any(muscle_name in tendon.name for muscle_name in FINGER_MUSCLE_NAMES)
```

finger muscle 表中存在很短的名称，例如 `OP`。如果未来模型加入名称中包含该子串的非手指 tendon，就可能被误删。

**修复**

- 从 actuator 精确解析其 tendon id；
- 删除被已确认 finger actuator 引用的 tendon；
- 或使用 canonical exact tendon naming，而不是任意 substring；
- 删除后 assert：所有预期 finger tendon 均不存在、所有非 finger tendon 数量与 hash 一致。

### Risk P1-6：可选 muscle observations 遍历全部 actuator，未检查 actuator type 和 actnum

`_get_observation_specification` 对 `spec.actuators` 中每个 actuator 都创建：

- ActuatorLength
- ActuatorVelocity
- ActuatorForce
- ActuatorExcitation
- ActuatorActivation

如果将来组合环境加入 motor、position actuator 或无 scalar activation 的 actuator，activation observation 可能无效。

**修复**

- length/velocity/force 根据 transmission 可用性验证；
- excitation 根据 control channel；
- activation 只在 `dyntype` 有 activation 且 `actnum==1` 时创建；
- 对非 muscle actuator 使用独立 observation schema。

### Risk P2-1：JAX backend 会关闭除 floor/ground 外的全部 contact

`MyoFullBody._modify_spec_for_mjx` 在非 Warp 路径中，把绝大多数 geom 的 `contype` 和 `conaffinity` 设为零。

对纯 body trajectory mimic 可能是性能优化；对以下阶段可能不适用：

- 球拍—羽毛球接触；
- 手—拍柄或附件接触；
- 自碰撞；
- 落地外的精细碰撞。

需要确认具体 Stage 2/3 是否使用独立场景并重新启用必要 contact。不要假设 JAX 与 Warp 的物理接触完全可比。

### Risk P2-2：activation energy 当前对整个 `data.act` 求均值

当前模型可能恰好只有肌肉 scalar activation，但未来加入其他带内部状态的 actuator 后：

```python
mean(data.act ** 2)
```

不再等于 354 个 body muscle 的 activation energy。

建议通过 exact ordered body actuator -> act address 映射计算，和 anatomy/synergy ABI 绑定。

### Risk P2-3：full-354 与 synergy 的 action metrics 语义不完全一致

基础 reward 收到：

- full-354：直接 354 维策略 action；
- synergy：已经解码、clip 后的 354 维 body action。

因此 `action_rate`、raw action overshoot 等指标不是完全同一层级。饱和率可以作为边界占用诊断，但应补充统一的：

- applied raw ctrl rate；
- effective excitation rate；
- actual activation rate。

### Risk P2-4：clip 后指标会隐藏 preclip residual 问题

只看最终 `decoded_excitation` 不能判断 basis/residual 是否频繁越界。应同时记录：

- preclip out-of-range fraction；
- clip correction RMS；
- residual contribution fraction；
- preclip intra loss；
- postclip intra loss。

### Risk P2-5：当前 regional grouping 不是 anatomy grouping

`pelvis_and_trunk` 一组覆盖约 211 个 actuator。它对区域 rank allocation 有用，但如果被误用于“生理肌肉分组”，会产生完全错误的约束。

建议 schema 名称和 loader 类型严格区分：

```text
regional_muscle_grouping_v1
anatomical_muscle_grouping_v1
emg_observation_mapping_v2
```

禁止交叉加载。

### Risk P2-6：资产依赖测试不是 PR 自动门禁

PR 的常规 CI 以 Ruff、source-only contract 为主；依赖完整模型资产的测试需要手工或 self-hosted 触发。当前 commit status 也没有提供可确认的完整运行结果。

对于这次改造，至少应让以下 smoke test 成为必跑：

- load exact MyoFullBody asset；
- assert 354 ordered actuators；
- build MJX model；
- one reset + one step；
- effective excitation roundtrip；
- activation address map；
- anatomy manifest binding；
- fixed synergy decode；
- intra loss JIT/vmap；
- one validation pass。

## 19. 论文中可以如何表述

建议叙事：

> 仅依靠运动学轨迹跟踪无法唯一确定肌肉募集方案。我们在模型层面区分三类结构：同一神经肌肉单元的数值作用线、同一广义肌肉的功能分区，以及跨肌肉的功能协同。对于经过模型与解剖审计确认的作用线，我们在 MuJoCo 实际 activation state 上施加带活动门控和 deadband 的内部一致性正则；对于不同功能分区，仅进行弱诊断而不强制相等。随后，我们将 354 维模拟 activation 通过显式观测映射投影到 15 个 sEMG 通道，并在相同动作事件坐标下比较真人与仿真的 NMF 协同结构和时序。该设计避免把表面 EMG 聚合、模型离散线段和跨肌肉协同混为同一种约束。

你可以把主要贡献概括为：

1. **模型语义层**：统一 policy action、effective excitation 和 activation；
2. **局部生理层**：经过审计的肌肉内部一致性；
3. **群体控制层**：多动作肌肉协同；
4. **真实验证层**：15 通道 sEMG 与事件时序对齐；
5. **任务层**：在不牺牲羽毛球轨迹/击球表现的前提下提高神经肌肉合理性。
